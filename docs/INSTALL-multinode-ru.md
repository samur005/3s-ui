# Установка 3S-UI: мастер, ноды, клиенты с входящими мастера и нод

Пошаговая инструкция для схемы «мастер + удалённые ноды». Названия пунктов
меню приведены по русскому интерфейсу панели.

> **Версия.** `install.sh` ставит **последний опубликованный релиз** GitHub
> (`releases/latest`). Мульти-нода в этом объёме (шифрование токенов, mTLS,
> очередь, заголовки подписки, qWDTT на нодах) есть только в релизе, собранном
> из `main` после слияния PR #18 и #19. Проверьте версию: `/usr/local/3s-ui/3sui -v`.

## 1. Мастер

### Установка

```sh
bash <(curl -Ls https://raw.githubusercontent.com/samur005/3s-ui/main/install.sh)
# с русским языком установщика и меню:
S3UI_LANG=ru bash <(curl -Ls https://raw.githubusercontent.com/samur005/3s-ui/main/install.sh)
```

Установщик спросит, менять ли настройки:

* **да** — введите порт и путь панели, порт и путь подписки, затем логин и
  пароль администратора;
* **нет** (новая установка) — будут созданы **случайные** логин и пароль; они
  выводятся один раз на экран, сохраните их.

Значения по умолчанию:

| | По умолчанию |
|---|---|
| Панель | порт `2095`, путь `/app/` → `http://<IP>:2095/app/` |
| Подписка | порт `2096`, путь `/sub/` |
| Логин / пароль по умолчанию | `admin` / `admin` (при установке через `install.sh` без настройки — случайные, см. выше) |

### Первый вход и смена учётных данных

* Откройте `http://<IP>:2095/app/` и войдите.
* Сменить логин/пароль: меню `3s-ui` → **6. Задать учётные данные
  администратора**, или командой:

  ```sh
  /usr/local/3s-ui/3sui admin -username <логин> -password '<пароль>'
  /usr/local/3s-ui/3sui admin -show      # показать текущие
  ```

  В интерфейсе — страница **Администраторы**.
* Порт/путь: `3s-ui` → **9. Настроить параметры панели** или
  `/usr/local/3s-ui/3sui setting -port 2095 -path /app/ -subPort 2096 -subPath /sub/`.
* HTTPS: **Настройки → Домены и сертификаты** (ACME) или `3s-ui` → **19**.

## 2. Нода

Нода — это **такая же панель 3S-UI**, отдельного «режима ноды» нет.

1. Установите панель на сервер ноды той же командой, что и мастер (раздел 1).
2. **API-токен для мастера:** на панели ноды откройте **Администраторы → API-токен →
   Добавить**. Скопируйте токен сразу: повторно он не показывается.
3. **Файрвол на ноде:**
   * порт панели (по умолчанию `2095/tcp`) открыт **только для IP мастера**;
   * порты входящих, к которым подключаются клиенты (например `443/tcp`,
     для qWDTT — `56000/udp` и, при raw-IP, `56003/udp`);
   * порт подписки ноды (`2096`) клиентам не нужен: подписку отдаёт мастер.
4. Лучше HTTPS: сертификат через **Настройки → Домены и сертификаты**, либо
   самоподписанный с пином на мастере (см. ниже). Если на ноде задан веб-домен,
   мастер должен обращаться по этому домену: при обращении по голому IP нода
   отвечает 403.

### mTLS (необязательно)

1. Создайте свой CA и клиентский сертификат мастера (любым инструментом PKI).
2. На ноде: **Настройки → Интерфейс → CA клиентских сертификатов мастера** —
   вставьте PEM вашего CA и сохраните. После этого API ноды (`apiv2`) отвечает
   только на запросы с сертификатом, подписанным этим CA. Вход в веб-интерфейс
   ноды работает как раньше.
3. На мастере в карточке ноды заполните **Клиентский сертификат (mTLS)** и
   **Клиентский ключ (mTLS)** (раздел 3).

> TLS должна завершать **сама панель** (её сертификат или ACME). За nginx или
> CDN, которые снимают TLS, сертификат до панели не дойдёт, и при включённом CA
> API ноды будет отказывать во всех запросах.

## 3. Добавление ноды на мастере

**Узлы → Добавить**, поля:

| Поле | Что указать |
|---|---|
| Название | уникальное; станет префиксом ссылок ноды в подписке: `[название] …` |
| Адрес панели | только `scheme://host:port`, напр. `https://1.2.3.4:2095` (без пути) |
| Веб-путь | путь панели ноды, по умолчанию `/app/` |
| API-токен | токен из шага 2.2 (только запись: при редактировании оставьте пустым, чтобы сохранить) |
| Пин сертификата (SHA-256) | для самоподписанного сертификата ноды (лучше, чем «Пропустить проверку TLS-сертификата») |
| Клиентский сертификат / ключ (mTLS) | только если включили mTLS на ноде |
| Группа, локация | произвольные метки для фильтров и массовых действий |
| Разрешить приватный адрес | нужно, если нода в LAN, на loopback или в CGNAT/Tailscale (100.64/10) |
| Исключить из подписок | серверы ноды не попадут в подписки (ничего не удаляется) |
| Режим синхронизации | **Односторонняя (мастер → узел)** — по умолчанию; двусторонняя только явно |

Нажмите **Проверить соединение**: должно появиться «Панель доступна» с задержкой
и версиями. Затем сохраните. Примерно через 5 с нода будет «В сети».

**Импорт входящих ноды (adoption).** На странице **Узлы** у ноды нажмите
**Импорт входящих**. Отметьте входящие ноды и при желании выберите, каким
клиентам их выдать: **Нет / Все / Группа / Клиенты**. Нажмите **Импорт входящих**.
На мастере появятся реплики этих входящих; именно их привязывают к клиентам.

Подробности ноды (иконка «глаз») открывают страницу `/app/node?id=N` со
вкладками: Обзор, Входящие, Исходящие, Клиенты, Маршрутизация, DNS, Возможности,
Трафик, Сервисы, Логи, Обновление, Дерево узлов, Очередь, Настройки, Аудит / Синхр.

## 4. Входящие на мастере и на ноде

* **На мастере:** **Входящие → Добавить**, выберите тип (VLESS, Trojan,
  Hysteria2, …), порт, TLS/REALITY, затем в блоке клиентов выберите, кому выдать
  входящее.
* **На ноде:** либо в панели самой ноды (**Входящие → Добавить**), либо с
  мастера: **Узлы → (глаз) → Входящие → Добавить** (JSON-редактор). Правки,
  сделанные прямо на ноде, мастер подхватывает на ближайшем heartbeat (5 с).
  После этого выполните **Импорт входящих** для новых входящих.
* **qWDTT (туннель через звонки VK):** **Входящие → Добавить → тип qwdtt**.
  * **Пользователи:** оставьте «Свой пароль у каждого клиента»; выберите
    клиентов.
  * **VK hash:** на странице **qWDTT** (боковое меню) вставьте cookies VK
    (JSON-массив `{name, value}` из экспорта браузера или заголовок `Cookie:`;
    обязателен `remixsid`). Затем включите автоматические hash или нажмите
    создание hash. Hash проверяется каждые 5 минут и при необходимости
    заменяется. Вместо cookies можно указать удалённую панель WDTT.
  * Откройте `56000/udp` (и `56003/udp` при raw-IP).
  * qWDTT-входящее **ноды** импортируется на мастер так же, как остальные
    входящие ноды. Ссылки `qwdtt://` для нод собираются автоматически.

## 5. Клиент с входящими мастера и ноды в одной подписке

1. **Клиенты → Добавить.** Задайте имя: оно же идентификатор подписки. Укажите
   лимиты при необходимости (объём, срок, лимит IP, **Лимит устройств (HWID)**).
2. Во вкладке входящих отметьте **и локальные входящие мастера, и
   импортированные входящие нод**. У входящих нод показано имя узла.
3. Сохраните. Мастер сам заводит этого клиента на ноде (в группе `@cluster`,
   синхронизация примерно за 5 с, плюс ежечасная сверка) и добавляет в подписку
   ссылки ноды с префиксом `[название ноды]`. Подписка обращается к ноде не при
   каждом запросе: ссылки хранятся на мастере, и при недоступной ноде отдаются
   последние известные.
   * Группа `@cluster` служебная: на ноде так помечены клиенты, которыми
     управляет мастер. Не создавайте клиентов этой группы вручную и не правьте
     их на ноде: мастер перезапишет изменения. Собственные клиенты ноды (вне
     `@cluster`) мастер не трогает.
   * Автопривязка `autoBindSyncedInbounds` — настройка без переключателя в
     интерфейсе, по умолчанию выключена. Она относится только к двусторонней
     синхронизации (входящие с `sync_uid`). В обычной схеме входящие выбираются
     у клиента вручную, как в п. 2.
4. **Ссылка на подписку и QR:** на странице **Клиенты** нажмите иконку QR у
   клиента: там ссылка подписки, ссылки по серверам и вкладка qWDTT. Формат
   адреса: `http(s)://<домен или IP>:2096/sub/<имя клиента>`. Внешний адрес
   задаётся в **Настройки → Подписка → URI подписки**. Варианты:
   `?format=json` (sing-box), `?format=clash`, `?format=happ`, `?format=qwdtt`
   (приложение qWDTT), `?format=page` (страница клиента), `?format=info`.
5. **Заголовки подписки:** **Настройки → Заголовки профиля**. Там задаются
   название профиля, ссылка на поддержку, страница профиля, объявление,
   маршрутизация (Happ/Incy), скрытие настроек и все заголовки Happ (включаются
   флажком «Определять Happ и слать заголовки Happ»). Работают подстановки `{{USERNAME}}`, `{{ID}}`,
   `{{TELEGRAM_ID}}`, `{{REMARK}}` и др. Произвольные заголовки (например
   `announce-url`) добавляются в **Настройки → Подписка → Дополнительные
   заголовки**. Полный список заголовков —
   [multi-node/subscription-headers.md](multi-node/subscription-headers.md).

## 6. Обновление, бэкап, откат

* **Обновление:** `3s-ui` → **2. Обновить** (или повторный запуск `install.sh`).
  Порядок обновления мастера и нод не важен. Панель ноды можно обновить и с
  мастера: **Узлы → (глаз) → Обновление** (проверка SHA256SUMS, версия
  фиксируется при подтверждении).
* **Бэкап:** **Главная → Резервное копирование и восстановление** или
  `/usr/local/3s-ui/3sui backup -output /root/3s-ui-backup.db`. Токены нод и ключи mTLS в базе
  **зашифрованы**. Ключ лежит в `/usr/local/3s-ui/db/secret.key` (или в
  переменной `SUI_SECRET_KEY`). **Сохраняйте `secret.key` вместе с бэкапом**:
  без него токены нод после восстановления на другом сервере читаются как
  пустые, и их придётся ввести заново.
* **Откат на старую версию:** сначала остановите панель и расшифруйте секреты
  новой версией, затем ставьте старую:

  ```sh
  systemctl stop 3s-ui
  /usr/local/3s-ui/3sui secrets -decrypt
  # затем установка нужной версии, напр.: 3s-ui → 3. Выбор версии
  ```
* **mTLS за nginx не работает** (см. раздел 2): для API ноды TLS должна
  завершать сама панель.
