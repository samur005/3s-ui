# Двусторонняя синхронизация (opt-in)

## Режимы узла (`nodes.sync_mode`)

| Режим | Поведение |
|-------|-----------|
| `one_way` (по умолчанию) | Как в v2.4.x: импорт реплик + push клиентов `@cluster` мастер→узел |
| `bidirectional` | Opt-in: обмен **записями с `sync_uid`** в обе стороны через reconcile |

Режим **никогда** не включается сам при добавлении узла.

## Идентичность и ревизии

- `sync_uid` — стабильный UUID сущности (не имя, не локальный `id`).
- `sync_rev` — монотонная ревизия на стороне, сделавшей правку.
- `sync_base` — ревизия, от которой шла правка (для детекции конфликта).
- `sync_origin` — id панели-источника последней принятой правки (анти-эхо).
- `deleted_at` — tombstone; физическое удаление только после подтверждения/срока.

Каждая панель имеет `panel_sync_id` в settings (генерируется при первом запуске bi-di).

## Что синхронизируется

### Клиенты (поддерживается)
Имя, enable, config (учётные данные протоколов), expiry, desc, limitIp,  
привязки к входящим **по `sync_uid` входящих**, tombstone.

**Не** синхронизируются: up/down/volume counters, tgId, links (пересчитываются локально),  
локальные клиенты без `sync_uid` (в т.ч. «свои» пользователи узла).

### Входящие — шаблон + локальные поля
**Шаблон (sync):** type, tag, enable, options **без** listen/listen_port,  
out_json **без** server/server_port/detour-адресов loopback.

**Только локально (не sync):** listen, listen_port, tls_id, addrs, volume/up/down, node_id,  
handoff-секреты Xray, WG/AWG ключи, qWDTT cookies/hash.

При создании с удалённой стороны локальные поля заполняются безопасными заглушками  
(listen `127.0.0.1`, порт 0 → оператор задаёт на месте) и помечаются `sync_needs_local=true`.

## Матрица протоколов (честная)

| Тип | Клиенты bi-di | Шаблон inbound | Полный клон секретов |
|-----|---------------|----------------|----------------------|
| vless, vmess, trojan, ss, hy2, tuic, … (sing-box с users) | да | да | credentials в client config — да |
| shadowtls v3 | да | да | handshake SNI — да; listen локально |
| xvless | да | частично | handoff user/pass/port — **нет**, пересоздаются локально |
| qwdtt | привязка | stub | cookies/hash — **нет** |
| wg / awg | привязка | stub | ключи сервера/пиров — **нет** |
| tun/redirect/tproxy/direct/cloudflared | нет | нет | n/a |

«Полная двухсторонняя» в UI означает режим обмена записями с `sync_uid`, **не** клонирование всех секретов и интерфейсов.

## Конфликты

Одновременные правки одной `sync_uid` с расходящимся `sync_base` → запись в `sync_conflicts`.  
Автоматического last-write-wins **нет**. UI: список конфликтов → принять локальную / удалённую / отложить.

## Удаления

`deleted_at` выставляется; противоположная сторона получает tombstone.  
Окончательное удаление — после **Подтвердить удаление** в UI или TTL (по умолчанию 30 суток, только если обе стороны ack).

## Анти-эхо

События с `sync_origin == panel_sync_id` при pull игнорируются.  
`@cluster` push в one_way не создаёт `sync_uid` на стороне узла как «локальную» правку для обратного потока без enroll.

## Совместимость версий

Bi-di требует, чтобы **обе** панели были ≥ версии с этим протоколом (`sync_proto=1` в handshake status).  
Иначе узел остаётся в `one_way` с предупреждением в UI.
